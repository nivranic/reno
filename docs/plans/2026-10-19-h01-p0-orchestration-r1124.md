## 1. 本批决定和可以确认的范围

将上一批的单 C body 候选收敛成两条具名路线：**每次调用独立的 effectful P0 orchestration J**，以及**catalog 原 maker 的 source witness D**。D 保存实际创建来源，J 保存本次实际执行结果；D 不保存 maker 的最近一次 tools、owner 或 context。两个对象不能合并成按模块第一次或最后一次返回值授信的槽。

静态输入新增 catalog 第四目标：四个 module 顶层语句共83条，其中原三模块78条、catalog 5条；catalog maker body 有18条直接语句、六个 inner def，返回顺序固定为 function_row、module_row、class_row、owner_storage、make_view、check_view。数量是 AST 语法库存，含 doc/future 和 inactive if False，不是运行次数。原三模块各一个 tool_rows GeneratorExp；保持真实惰性 generator 是明确约束。

比较三条路线：继续从 current module maker/getter 建 expected 缺独立来源，不选；仅创建 J/factory/facts 的 effectless 层不能包含 P0 发布或原业务 body，不作为 P0 完整 producer；选择同一 C body 持根并按原顺序驱动 effectful P0，承担执行边界变化并逐项审查。选择一个方向不等于其所有协议已批准。

本轮撤回一个调查假设：3.12.10 原 MAKE_FUNCTION 本身调用 PyFunction_New(codeobj, GLOBALS())，不是直接用固定 frame B 创建所有 private function。public New 同样从 current G 解析 builtins，缺席时再沿当前 Python frame fallback。因此“原 MAKE_FUNCTION 固定继承 B，而 public New 额外重读 G”不能作为否决理由。hidden module M 的 EvalCode 私有 constructor 是另一对象，仍保持原路线。真正需要接的是 New 返回后 closure/annotations/kwdefaults/defaults/version 后填、actual return、原 STORE 和执行边界。

## 2. 四目标与可信边界

范围固定为 catalog/control/scope/registration，不是通用 Python AST 解释器。原 PathFinder 槽代理、单次实际 get_code、原 helper/builtin exec、actual K/G 与 hidden M 继承 r1111/r1112/r1121；未来 K 必须针对实际新源码/编译结果审查，本批没有这样的 K。

拟议的三模块 K 在原 module 进入 reserved native ingress。C 使用来源于实际 loader attempt A 的 code 根/G，不从传入 subject、current module 属性或 current function.__code__ 生成 expected；每次调用建立全新的 J，并在自己的 C 活动调用中持根。reserved 读取不是秘密，也不证明调用者不可伪造。外部从另一 Python frame 调用同一个原 C 时建立的是 J2，其实际环境 X2 不冒认 J1 的 X1；必须按独立调用的原路线建立根并执行相应 effect。

同一 C body 在其 Python callee 活动时，公开环境 getter 得到的是 callee frame 的环境；只有 callee 返回后才恢复外层调用环境。不能在 maker/helper 活动期间取一个 B，再称其为原 module B。使用 actual current environment 的时点、G 内 __builtins__ 与缺席 fallback 分列，不能用 post-helper 回调补回原 module 的首次来源。

catalog 也要进入受审 native producer 路线。它的实际 maker 必须先由 actual catalog K 的后代 code/G/当次环境创建并独立持有，随后才另行原 maker STORE/effect。不能只改后三模块、继续把 catalog 当前同名属性当来源。

## 3. source witness D：运输可以不可信，expected 不能来自运输值的重 pin

拟新增一个 catalog 私有运输 alias `_AUTH_CATALOG_SOURCE_WITNESS`。它不是秘密，也不以 module 属性的当前位置建立信任。D 必须由固定 native producer 在 actual maker 创建成功后直接构造；不提供接收任意 function/code/G 来登记来源的 Python API，不开放实例化、dict、可写字段或自有 phase setter。

D 的原生字段保存：原 native module/type/state 归属、catalog 的实际 A/原 K/原 module G、实际 New 返回的 maker、CREATE 前独立 expected 及后填后的完整 metadata 基线、内部初始化阶段。实际字段数量、各版本结构和 N4 尚待完整设计；这里不以 exact type 一项代替全部实际构造/归属证明。D 的所有字段只从固定实际 producer 路线填入，不从新运输 alias 或 observed maker 回填 expected。

在后续三模块 J 中保原 importer 及原 maker alias 的一次原属性观察，先持住 actual imported module、actual observed maker；该原观察若抛错，直接保其first，不为 D 增读覆盖。随后先核实际原 module/原dict类型与所有键，再从其 raw dict 额外读取 D 作为不可信运输；D缺席直接拒绝，不触发 module.__getattr__。先核 actual D 的原 native type/state/初始化状态与同解释器归属，再核 actual module G、D 的 A/K 来源、actual observed maker 正是 D 强持的实际 New 返回；在同次实际调用点联合 fresh metadata/G/B/必要 phase 后，才用这个已选 callee 及已准备参数实际调用。不在 dispatch 重新 lookup maker，不从它读取 current code 作为 expected。D不是caller身份认证，也不是maker返回六工具已经通过的证书。

新 alias 发布与原 maker 发布是两次不同 effect：增加 D allocation/STORE/可再入释放、可观察名称和独立失败前缀。时点选择为原 maker New/后填/检查→本方持根→原 maker STORE/effect→新 D alias 发布；D 所需分配/字段准备与其真正发布分列。原 maker STORE 失败不补发布 D；新 D 发布失败时，原 maker 与 earlier imports/doc 等 effect 可能已存在，保原 partial，不删除、回滚、补发布或重试来伪装原子成功。原 STORE callback 内若重入并观察到 maker 而 D 尚缺，消费拒绝且不修复；这个新增可再入失败也是明确 delta，不能宣称不存在窗口或全部透明。**此时点是拟议 delta，不宣称与原语义等强或已获完整批准。**

alias 缺席、错类型、跨 G、错 A、未完成/退休或 observed maker 不同均拒绝，不自修 alias、不认领 current。D发布失败可能留下“新maker已写、旧D仍在”的partial，后续因actual maker/D不匹配拒绝，不清除旧值假装未发生。合法旧 D 与其 actual old maker 若同 A/G、来源仍有效且本次完整谓词仍成立，可作为多个真实原构造实例中的一个选择；原契约没有统一要求必须是最近一次 import/reload 的 maker。它不能为新 maker 补 pin，不宣称最新，也不能给别的 J 提供最后 tools/owner。若某条具体消费另有独立代际/phase 要求，仍按该要求拒绝。

D 并不解决 maker 的六个实际返回 function 的来源和闭包消费。它们仍需独立 code 路径、actual producer/return/原 closure cells、独立 primitive expected 与同次验证，不能在 C 获得返回 tuple 后仅逐字段自洽快照就宣称源码来源闭合。

## 5. 具体 API 可行处和仍不能“直接改写”的位置

**private function 创建。** 3.12.10 MAKE_FUNCTION 使用 public PyFunction_New；可继续以 actual child code/G、同一次 C 环境和原 qualname 路线设计 native 创建。CREATE 内允许合法 watcher；返回后不能假定 metadata 未变。原 MAKE_FUNCTION 后填 closure、annotations、kwdefaults、defaults，并设置 func_version。当前27顶层 def 的头为空不能替代 generator、catalog inner defs、lambda 或未来 K 审核；PyFunction_Set* 的事件/错误不自动等同直接后填。没有实际版本源码及字段方案前不宣称 New 已完全等价。hidden M 不走这条替换。

**IMPORT_NAME。** 必须从原 module 的实际 B 读取实际 __import__，保 name/G/L/fromlist/level 五项，overridden importer 仍允许。原 default 分支先释放 import_func，再转换 level，调用 PyImport_ImportModuleLevelObject；overridden 分支只实际 call 一次再释放。原 name/fromlist/level 对象来自 actual K 对应槽，不能按 AST 内容重造对象后声称身份观察相同。C current B getter 只在正确的外层时点可作环境来源，不冒认实际 L；L 从本次原 wrapper/attempt 的 C-held 根转交，不读取真实 frame/locals。default 身份判定、原释放顺序及错误仍须按实际版本实现并复审。

**IMPORT_FROM。** 原 import_from 是 ceval.c 静态函数，包含原属性查找、循环导入 sys.modules fallback 和具体 ImportError 构造。不能从扩展直接假称链接该静态符号，也不能只 PyObject_GetAttr 一次当作等价替代。保留真实原 IMPORT_FROM 执行的 fragment 路线会增加 Python frame/hidden M/环境/extra CREATE 与可再入边；公开 API 重建路线又须逐条证明原错误和 fallback。**两条路线本批均未闭合，此处是具体实施阻塞，不能以通用 PyImport API 跳过。**

**generator。** 保留真实 generator/原左 GET_ITER、lazy body 与 tuple target 是优先约束。只 C 驱动原 generator code 仍不解决其 body 再读 current tools[0] 后实际 call 的来源门。必须在实际 body call 处接原 native consumer 和独立 expected，或提出具体 generator ABI/closure/code 变化并审核。外层返回后再校验 rows 不会补回此前未知 callee 已执行；不能报 P05 已闭。

这四处把“C 有能力执行操作”与“原合同已保且来源已闭”分开。下游完整设计必须给可链接 API、actual operand/source 和错误/引用路线，不能继续用任意 EvalCode fragment 或 callable wrapper 作未展开占位。
