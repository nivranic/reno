# 运行成本与配额实证(开发期记录)

## 实测:智谱 Coding Plan 配额特性(2026-09-19 晚实测)

- **批处理会打穿配额**:20 视频批量(VLM 22帧/视频 + atomize 重试)连续跑约 40 分钟后,API 进入 429 限流,**恢复窗口 > 15 分钟**(停止所有调用后仍持续),推测为小时级 token/请求窗口。
- **结论:coding plan 适合两类负载**
  1. 开发与调试(交互式、间歇);
  2. 日常增量采集(每天几个~十几个视频的节奏);
  **不适合**:一次性全量回填(几百视频)。全量回填应分日执行,或改用按量付费 key。
- **缓解措施(已进代码)**:
  - `thinking.type=disabled`(结构化抽取不需要深思考;大幅降 token 与时延);
  - 429 指数退避 6/18/54s + 请求重建;
  - VLM 帧循环 pacing(每 5 帧歇 1s);
  - read timeout 按 max_tokens 缩放(非流式下 read 超时=总生成时长,实测深思考长输入可 >8 分钟);
  - 看护脚本 `scripts/quota_guardian.sh`(探测恢复自动续跑,分日回填的无人值守形态)。

## 单视频成本量级(推导值,非官方报价)

- VLM:22 帧 × (~500 视觉 in + ~120 out) ≈ 11K in + 2.6K out /视频
- atomize:timeline(~3-8K in)+ 原子 JSON(~1.5-3K out)/视频
- judge:候选对批次 ~2-6K in / 全库重跑
- 量级:每视频约 1-2 万 token 级 —— coding plan 月配额支撑**日常增量**充裕,支撑**全量回填几百视频**紧张(与上面结论一致)。
